# 原型工具落地 SOP(国产设计工具)

> 目的:把 PMAgents 产出的原型产物(规格文档 + HTML 低保真原型)落地为国产设计工具中的正式设计稿。
> 分三阶段推进,不写死工具的具体 API 细节(工具能力迭代快,实现前需按本文档验证)。

## 产物基础(一期,已实现)

PMAgents 的原型步骤(`python main.py step prototype`)产出两个文件:

1. `artifacts/06_prototype_spec.md` — 原型规格文档,四节:
   - 页面清单(页面名/目的/入口/导航)
   - 组件清单(名称/类型/状态/复用性)
   - 交互说明(操作 → 触发条件 → 系统反馈)
   - 文案清单(内容/位置/语气)
2. `artifacts/07_prototype.html` — 单文件 HTML 低保真原型(内嵌 CSS/JS、零外部依赖、页面可跳转、核心交互可演示)

**HTML 原型本身就是可评审、可演示的原型**:浏览器打开即用,可发给任何人。国产工具主要用于把它提升为高保真设计稿。

## 阶段二:AI 转稿 + 人工精修(推荐路径,人工操作,无需代码)

通用流程:

1. 打开 `07_prototype.html`,确认交互流程符合预期(原型走查)
2. 在目标设计工具中使用其 AI 能力,以规格文档 + HTML 为输入生成设计稿
3. 人工精修:配色、组件库替换、图标、状态补全
4. 评审定稿

各工具使用要点(实现前需验证的能力已标注):

| 工具 | 使用方式 | 需验证 |
|------|----------|--------|
| 墨刀 | 用「墨刀 AI」以原型规格文档的文字描述生成页面,或导入 Axure/HTML 后调整 | 个人版是否开放 AI 生成入口;「HTML 转设计稿」能力与中文还原度 |
| 即时设计 | 用「即时 AI」生成画板,对照规格文档与 HTML 原型调整 | 能否接受 HTML 文件导入;生成画板的可用性 |
| MasterGo | 用「MasterGo AI」生成页面框架,人工替换为团队组件库 | 个人版 AI 功能入口与导出格式 |

## 阶段三:开放平台程序化导入(条件性做,需先验证)

目标:把 `06_prototype_spec.md` 的页面清单 + 组件清单通过代码转换为设计文件(画板/图层)。

候选工具:即时设计(开放平台 REST API)、MasterGo(插件 API)。

**启动前必须验证的三件事,缺一不可:**

1. 能通过代码创建画板与基础图层(矩形/文本/图形)
2. 能设定组件属性(位置/尺寸/颜色/文本)
3. 有可用测试配额与稳定认证方式(个人账号可用)

验证通过后再写导入脚本(建议作为 CrewAI 自定义工具接入原型步骤);验证不通过则停留在阶段二的人工路径。

## 明确不做

- 插件级深度集成(PRD 变更自动同步设计稿)
- 设计稿反向生成代码
- 这些依赖强绑定且价值未验证,等个人提效场景跑顺后再评估。
